# הדקדוק של JavaScript ושל TypeScript

הקובץ הזה עונה על שאלה אחת: **מה בדיוק כתוב כאן, ולמה זה כתוב כך.** לא מה זה עושה בזמן ריצה (זה `concepts.md`), אלא מהי הצורה התחבירית, מאילו חלקים היא מורכבת, מה חובה ומה אופציונלי, ומה הצורות החלופיות לאותו דבר.

השתמש בו בסעיף 3 של השיעור. **קח רק את המשפחות שהקובץ הנלמד באמת מציג**, ופרק כל צורה לחלקיה במקום להסתפק בשם שלה. הכלל: כשמופיע תו שנראה כמו רעש, עצור והסבר מה הוא.

## 1. הצהרות וקישור שמות

שלוש מילות הצהרה, ורק שתיים בשימוש:

- `const` — הקישור אינו ניתן לשינוי. **הערך כן.** `const a = []` ואז `a.push(1)` חוקי לחלוטין: אסור להשים ל-`a` ערך אחר, מותר לשנות את מה שהוא מצביע אליו. זו הצהרה על השם, לא על התוכן.
- `let` — קישור שניתן לשינוי, בתחום הבלוק.
- `var` — הצורה הישנה, בתחום הפונקציה ולא הבלוק. אם היא מופיעה בקוד מודרני זו כמעט תמיד טעות. לא בשימוש בפרויקט הזה.

ברירת המחדל בקוד הזה היא `const`, ו-`let` מופיע רק כשבאמת משנים את הקישור. זה מידע: `let` הוא סימן שמשהו זז.

## 2. פונקציות

### פונקציית חץ

הדקדוק המלא:

```javascript
(פרמטרים) => { גוף עם return }
```

וההקלות, שכל אחת מהן שינוי דקדוקי ולא סגנוני:

```javascript
(a, b) => { return a + b; }   // הצורה המלאה
(a, b) => a + b               // גוף-ביטוי: בלי מסולסלים, ההחזרה משתמעת
a => a + 1                    // פרמטר יחיד: מותר בלי סוגריים
() => doSomething()           // בלי פרמטרים: הסוגריים חובה
```

**המלכודת הדקדוקית המרכזית:** סוגריים מסולסלים אחרי `=>` נקראים כגוף פונקציה, לא כאובייקט. כדי להחזיר אובייקט מגוף-ביטוי, עוטפים בסוגריים עגולים:

```javascript
() => { a: 1 }      // מחזיר undefined. ה"אובייקט" נקרא כגוף עם תווית
() => ({ a: 1 })    // מחזיר אובייקט
```

### פונקציה רגילה

```javascript
function name(a, b) { return a + b; }
```

ההבדל התחבירי הוא קוסמטי. ההבדל האמיתי הוא ב-`this` וב-hoisting, ומוסבר ב-`concepts.md`. בקוד React מודרני פונקציות חץ הן ברירת המחדל, ולכן כמעט לא רואים `this` בפרויקט הזה.

### פונקציה שמחזירה פונקציה

```javascript
(i) => i + 1
```

כשזה מועבר כארגומנט, זו לא קריאה אלא **ערך**. ההבחנה הזאת קריטית וחוזרת בכל מטפל אירועים: `onClick={fn}` מעביר פונקציה, `onClick={fn()}` קורא לה מיד ומעביר את התוצאה.

## 3. פירוק והרכבה

### פירוק אובייקט

```javascript
const { a, b } = obj;                    // בסיסי
const { a: renamed } = obj;              // שינוי שם
const { a = 5 } = obj;                   // ברירת מחדל אם undefined
const { a: renamed = 5 } = obj;          // שניהם יחד
const { a, ...rest } = obj;              // rest: כל השאר לאובייקט חדש
const { a: { b } } = obj;                // מקונן
```

הצורה הזאת עובדת גם **בחתימת פונקציה**, וכך נראית כל קומפוננטה בפרויקט:

```javascript
const Logo = ({ className = "", height = 32 }) => { ... }
```

הפונקציה מקבלת ארגומנט **אחד** (אובייקט ה-props), ומפרקת אותו מיד לשמות מקומיים תוך קביעת ברירות מחדל. אין כאן שלושה פרמטרים.

### פירוק מערך

```javascript
const [first, second] = arr;
const [, second] = arr;          // דילוג על מיקום
const [head, ...tail] = arr;
```

לפי **מיקום**, לא לפי שם. לכן `const [value, setValue] = useState(0)` עובד, והשמות נבחרים על ידי הכותב.

### שלוש הנקודות

אותו תו, שני תפקידים הפוכים, והתפקיד נקבע לפי המיקום:

```javascript
const merged = { ...a, ...b };        // פיזור: פורק החוצה
const copy = [...arr];
function f(...args) { }               // איסוף: אוסף פנימה
const { a, ...rest } = obj;
```

בפיזור אובייקטים, **מי שמאוחר יותר גובר**: `{ ...a, x: 1 }` דורס את `a.x`.

## 4. מחרוזות

שלושה סוגי מרכאות. הראשונים שני זהים, השלישי שונה מהותית:

```javascript
'טקסט'
"טקסט"
`טקסט עם ${ביטוי} בפנים`
```

הגרש האחורי (backtick) הוא **מחרוזת תבנית**. `${...}` הוא חלון לביטוי JavaScript מלא, לא רק שם משתנה: `${a > b ? "כן" : "לא"}` חוקי. מחרוזות תבנית גם משתרעות על כמה שורות בלי תו בריחה.

בפרויקט הזה זה הכלי המרכזי להרכבת `className`:

```javascript
className={`בסיס ${תנאי ? "א" : "ב"} ${מבחוץ}`}
```

## 5. אופרטורים שנראים כמו רעש

זה הסעיף שהכי כדאי לעצור עליו, כי אלה התווים שהופכים קוד מודרני לבלתי קריא למי שלא ראה אותם.

### `?` — ארבעה תפקידים שונים לפי מיקום

```typescript
x ? a : b        // תלת-מקומי: תנאי
name?: string    // ב-TypeScript: שדה אופציונלי
obj?.field       // שרשור אופציונלי
a ?? b           // איחוד אפסי
```

זה לא אותו אופרטור. המיקום קובע.

### `?.` — שרשור אופציונלי

```javascript
obj?.field           // undefined אם obj הוא null/undefined, במקום לזרוק
obj?.method?.()      // גם לקריאות
arr?.[0]             // גם לאינדקס
```

עוצר את השרשרת ומחזיר `undefined` במקום לקרוס. חוסך את שרשרת ה-`if` המגנה.

### `??` מול `||`

```javascript
a ?? b     // b רק אם a הוא null או undefined
a || b     // b על כל ערך שקרי, כולל 0 ו-"" ו-false
```

זה מקור באגים אמיתי. אם `a` הוא מספר שעשוי להיות `0` לגיטימית, `||` יבלע אותו. `??` לא.

### `!` — שני תפקידים

```javascript
!x                         // שלילה לוגית
document.getElementById("root")!    // ב-TypeScript: "אני מבטיח שזה לא null"
```

השני הוא **טענת אי-אפסות**, ומופיע בסוף ביטוי. הוא משתיק את המהדר ולא בודק דבר בזמן ריצה. ב-`main.tsx` הוא מופיע בדיוק פעם אחת ובמקום מוצדק.

### `&&` כאופרטור רינדור

```javascript
{cond && <div />}
```

`&&` מחזיר את **הערך**, לא בוליאני: אם `cond` שקרי הוא מחזיר את `cond` עצמו. מכאן המלכודת המפורסמת ביותר ב-JSX: אם `cond` הוא המספר `0`, על המסך יופיע אפס. עם `list.length && ...` זה קורה, ולכן כותבים `list.length > 0 && ...`.

## 6. אובייקטים ומערכים

```javascript
const o = { a, b };              // קיצור: שקול ל-{ a: a, b: b }
const o = { [key]: value };      // מפתח מחושב
const o = { f() {} };            // קיצור מתודה
```

מערכים מעובדים כמעט תמיד בפונקציות סדר גבוה ולא בלולאות:

```javascript
arr.map(f)        // מחזיר מערך חדש באותו אורך
arr.filter(f)     // מחזיר תת-מערך
arr.find(f)       // מחזיר איבר יחיד או undefined
arr.some(f)       // בוליאני
arr.reduce(f, x)  // צובר לערך אחד
```

כולן מחזירות ערך חדש ולא משנות את המקור. ב-JSX זו הצורה היחידה שנקראת טבעית, כי `for` הוא משפט ולא ביטוי ואי אפשר לשים אותו בתוך `{}`.

## 7. מודולים

שתי צורות ייצוא, ולהן שתי צורות ייבוא:

```javascript
export default Logo;              // ייצוא ברירת מחדל: אחד לקובץ
export const A = 1;               // ייצוא בשם: כמה שרוצים
export type { Course };           // ייצוא טיפוס בלבד

import Logo from "./Logo";        // ברירת מחדל: השם נבחר על ידי המייבא
import { A, B } from "./x";       // בשם: חייב להתאים
import { A as B } from "./x";     // שינוי שם
import type { Course } from "./y" // ייבוא טיפוס: נמחק בקומפילציה
import * as All from "./x";       // הכול לאובייקט אחד
import "./index.css";             // רק לתופעת הלוואי
```

הבחנה שכדאי לזכור: ייצוא ברירת מחדל הוא **מיקום**, ולכן המייבא בוחר שם. ייצוא בשם הוא **שם**, ולכן הוא חייב להתאים. הצורה האחרונה, ייבוא בלי קישור, מופיעה ב-`main.tsx` לטעינת CSS.

## 8. הדקדוק של TypeScript

TypeScript הוא JavaScript ועוד שכבת הערות טיפוס. **כל התחביר בסעיף הזה נמחק בקומפילציה** ולא קיים בזמן ריצה.

### הערת טיפוס

נקודתיים אחרי השם:

```typescript
const x: number = 5;
function f(a: string): boolean { ... }
const g = ({ a }: Props) => { ... }
```

ברוב המקרים אפשר להשמיט: המהדר מסיק את הטיפוס. כותבים אותו במקומות שבהם הוא חוזה, כמו ב-props.

### כינוי טיפוס

```typescript
type Props = { a: string; b?: number };
```

מפריד בין השדות הוא `;` או `,`, ושניהם חוקיים. `?` אחרי השם הופך את השדה לאופציונלי, כלומר הטיפוס שלו נעשה `string | undefined`.

### איחוד וחיתוך

```typescript
type A = "x" | "y";           // איחוד: אחד מהם
type B = Base & { c: number }; // חיתוך: גם וגם
```

איחוד **ליטרלי** הוא הצורה שהכי מפתיעה מי שמגיע משפות אחרות: מחרוזות בודדות מורמות לדרגת טיפוס. `"default" | "white"` הוא טיפוס בן שני ערכים חוקיים בדיוק. אין enum ואין מחלקה.

### גנריות

```typescript
Array<string>
Record<string, number>
useState<number>(0)
```

זוויתיים אחרי שם, כמו תבניות. ההבדל הוא שמערכת הטיפוסים כאן מחשבת על טיפוסים ולא רק מחליפה אותם.

### `as const`

```typescript
const a = ["x", "y"];             // הטיפוס: string[]
const b = ["x", "y"] as const;    // הטיפוס: readonly ["x", "y"]
```

מקפיא את הערך ומצמצם את הטיפוס לליטרלים המדויקים. `ACTIVE_COURSE_SLUGS` משתמש בזה כדי שהטיפוס יידע בדיוק אילו סלאגים קיימים.

### טענת טיפוס

```typescript
x as HTMLElement
document.querySelectorAll<HTMLElement>("...")
```

אומרת למהדר "תאמין לי". לא ממירה ולא בודקת דבר בזמן ריצה. שונה מהמרה בשפות אחרות, ובדיוק לכן מסוכנת.

### הרחבת טיפוס גלובלי

```typescript
declare global {
  interface Window { __lenis?: { ... } }
}
```

מוסיפה שדה לטיפוס קיים מבחוץ. `scrollLock.ts` משתמש בזה כדי לתאר את המופע של Lenis שנתלה על `window`.

## 9. הדקדוק של JSX

JSX הוא **הרחבה תחבירית**, לא HTML ולא מחרוזת. הוא מתקמפל לקריאת פונקציה שמחזירה אובייקט, ולכן הוא ביטוי לכל דבר: אפשר להחזיר אותו, לשמור במשתנה ולייצר ב-`map`.

```jsx
<div className="x" />                  // אלמנט ריק, נסגר בעצמו
<div>{expression}</div>                // {} הוא חלון לביטוי JavaScript
<div style={{ fontSize: 12 }} />       // שני זוגות: החיצוני חלון, הפנימי אובייקט
<Comp {...props} />                    // פיזור props
<>{children}</>                        // Fragment: קיבוץ בלי אלמנט עוטף
{cond && <div />}                      // רינדור מותנה
{list.map(x => <li key={x.id} />)}     // רשימה
```

כללי הדקדוק שחורגים מ-HTML:

- `className` ולא `class`, `htmlFor` ולא `for`. שתי המילים שמורות ב-JavaScript.
- תכונות ב-camelCase: `onClick`, `strokeWidth`, `aria-label` (זו האחרונה נשארת עם מקף, כי היא לא מזהה JavaScript).
- כל אלמנט חייב להיסגר, גם `<img />` ו-`<br />`.
- **החזרה אחת בלבד.** כמה אלמנטים אחים חייבים עטיפה, ולכן קיים ה-Fragment.
- בתוך `{}` מותר רק **ביטוי**. `if` ו-`for` הם משפטים ולכן פסולים שם, ומכאן שהתלת-מקומי ו-`map` אינם סגנון אלא הכרח.
- ערך `{}` מקבל ביטוי; ערך במרכאות מקבל מחרוזת קבועה. `height={36}` הוא מספר, `height="36"` הוא מחרוזת.

## 10. אסינכרוניות

```javascript
const f = async () => {
  try {
    const res = await fetch(url);
    const data = await res.json();
  } catch (err) { }
};
```

- `async` על פונקציה גורם לה להחזיר `Promise` תמיד, גם אם הגוף מחזיר ערך רגיל.
- `await` חוקי **רק בתוך** פונקציה עם `async`.
- `await` לא חוסם חוט. הוא מפצל את הפונקציה בנקודה הזאת ורושם את ההמשך בתור.
- `try/catch` סביב `await` תופס גם דחיות של ה-Promise, ולכן זו הצורה הרגילה לטפל בשגיאת רשת.
